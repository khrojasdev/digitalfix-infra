# Datos de prueba

Dos scripts SQL sueltos, uno por microservicio. Se ejecutan con cualquier cliente
—SQL Developer, DBeaver, `sqlplus`— sin instalar nada.

| Archivo | Conectarse como | Lo crea |
|---|---|---|
| `seed-usuarios.sql` | `DFX_USUARIOS` | `ms-digitalfix-usuarios` |
| `seed-catalogo.sql` | `DFX_CATALOG` | `ms-digitalfix-catalog` |

La clave de ambos esquemas en desarrollo es `digitalfix`.

## Antes de ejecutarlos

Los scripts **llenan tablas, no las crean**. Cada microservicio tiene que haber
arrancado al menos una vez para que Flyway haya aplicado sus migraciones.

Si sale `ORA-00942: table or view does not exist`, es exactamente eso: ese
microservicio todavía no ha corrido. Levántalo una vez y vuelve a ejecutar.

## Cómo ejecutarlos

**Desde consola:**

```bash
sqlplus DFX_USUARIOS/digitalfix@//localhost:1521/XEPDB1 @seed-usuarios.sql
sqlplus DFX_CATALOG/digitalfix@//localhost:1521/XEPDB1 @seed-catalogo.sql
```

**Desde SQL Developer o DBeaver:** abre el archivo con la conexión que
corresponde y ejecútalo completo — `F5` en SQL Developer, *Ejecutar script* en
DBeaver. No sirve ejecutar línea por línea: los bloques `BEGIN ... END;` tienen
que ir enteros.

**Con el script de PowerShell**, si prefieres que lo haga todo de una:

```powershell
.\seed\sembrar.ps1
```

Ambos son **idempotentes**: se pueden correr las veces que haga falta. Una
empresa se reconoce por su nombre —ignorando acentos y mayúsculas—, un usuario
por su `AZURE_OID`, un servicio por `(empresa, código)` y un repuesto por
`(empresa, SKU)`. Volver a ejecutarlos no duplica nada ni pisa lo que ya existe.

## Qué queda cargado

### Usuarios

**20 empresas** de mantención eléctrica. Las tres primeras coinciden con las que
ya inserta la migración `V3`, así que se reconocen y se reutilizan en lugar de
duplicarse.

**81 usuarios**: cuatro por empresa, uno por cada rol del caso (`ADMIN`,
`SUPERVISOR`, `CLIENTE`, `AUDITOR`), más uno desactivado en la primera empresa
para poder probar que el sistema lo rechaza.

Los `AZURE_OID` siguen un patrón predecible, que es lo que los hace útiles para
probar:

```
seed-emp01-admin          admin.emp01@digitalfix.cl
seed-emp01-supervisor     supervisor.emp01@digitalfix.cl
seed-emp03-auditor        auditor.emp03@digitalfix.cl
seed-emp01-desvinculado   (activo = 0)
```

### Catálogo

Cuatro servicios y cinco repuestos en cada una de las **tres primeras empresas**,
más una asociación repuesto-servicio.

`BRK-16A` queda con stock 3 y mínimo 5 **a propósito**: es el caso que `HU-19`
tiene que hacer visible apenas se abre la pantalla de repuestos.

Tres empresas y no veinte porque con tres ya se demuestra lo único que hay que
demostrar aquí, que una empresa no ve lo de otra. Con veinte, la pantalla se
llena de ruido y la demostración se pierde.

## Dos detalles que evitan problemas

**El contador de las claves primarias.** Las migraciones `V2` y `V3` de usuarios
insertan filas con el `ID` explícito (1, 2, 3, 4) en una columna
`GENERATED BY DEFAULT AS IDENTITY`. Oracle **no adelanta el contador** cuando el
identificador viene dado, así que el siguiente `INSERT` automático intentaría
usar el 1 y fallaría con `ORA-00001`. El script lo reposiciona antes de insertar
nada. Si no lo hiciera, la semilla reventaría en la primera fila.

**Los acentos.** La migración `V3` inserta `ElectroRed Valparaíso` con tilde. Si
comparáramos los nombres tal cual, la semilla no reconocería esa empresa y
crearía una segunda casi idéntica. La comparación ignora acentos y mayúsculas.

## Para comprobar el aislamiento entre empresas

Con el catálogo levantado:

```powershell
# la empresa 1 ve sus servicios
Invoke-RestMethod http://localhost:8082/api/catalog/services `
  -Headers @{ "X-Company-Id"="1"; "X-User-Oid"="seed-emp01-admin"; "X-Roles"="ADMIN" }

# la empresa 2 ve los suyos, que son otros
Invoke-RestMethod http://localhost:8082/api/catalog/services `
  -Headers @{ "X-Company-Id"="2"; "X-User-Oid"="seed-emp02-admin"; "X-Roles"="ADMIN" }
```

Pedir por identificador un servicio de otra empresa devuelve **404**, nunca 403:
un 403 confirmaría que ese recurso existe.
